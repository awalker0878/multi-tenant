# G11 review — Pilot and supported release

This procedure applies the [canonical G11 criteria](../../implementation/gates.md) to the scope delivered by [P11](../../implementation/phases/p11.md). Use the [shared review process](README.md); the [delivery register](../../implementation/delivery-register.yaml) owns actual evidence references, reviewer identities and the gate decision.

**Review roles:** SRE, security, product/application, receiving operations, service, records and qualification reviewers.

**Environment:** Production readiness review and separately authorized bounded pilot; recovery exercise in its approved environment.

## Assemble the review packet

Production commissioning and change scope, Q10 pilot outcomes, independent operator handover, signed release identities and historical disposition.

Confirm the source/artifact identities, selected scope, authorization references, independent observation and evidence validity before judging results. Resolve missing artifacts as explicit review gaps.

## Review in this order

1. **G11.01:** Compare environment, tenant/site scope, credentials, backups, monitoring and windows with the qualified release and actual production authority. Resolve material drift before pilot enablement.
2. **G11.02:** Assess trained independent operators’ bounded tasks over the agreed observation period. Review application integrity, usable service, accessibility/performance and pilot stop/defect decisions.
3. **G11.03:** Observe someone other than the developer installing/recovering through released runbooks. Review support escalation and audit export without expanded unauthorized writes.
4. **G11.04:** Reconcile signed manifest, installed digests, tested support and published limits. Review archive/import or non-applicability for retained history; require separate authority before old-system retirement.

## Stop and corrective work

Missing receiving-team acceptance, unqualified pilot drift, release/evidence mismatch or unresolved required historical disposition prevents release closure.

Retain failed/missing cases and assign corrective work to the owning package with an unblock condition. A changed supported scope must be reflected in requirements coverage, the support matrix and the run manifest before another decision.

## Record the decision

Record an assessment for each G11 criterion, immutable evidence IDs and limitations, actual reviewer/date, blockers and the reviewed scope. Apply [status rules](../../implementation/status-model.md); a review document or a passing subset does not close the gate.

Identify material changes that require reruns, update the register, regenerate derived progress/traceability and state the next executable action. This gate review does not itself authorize unrelated native or production changes.
