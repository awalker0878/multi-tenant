# P03 completion review

The Catalogue slice delivers complete portable intent, immutable revisions, current
authority checks, ordered durable events and Console authoring/history journeys.
The [implementation record](p03-catalogue.md) identifies the qualified source and
the [coverage matrix](../../verification/p03/check-matrix.md) maps executable checks
to G03. P01/P02 receiving obligations remain separate and unchanged.

This packet supplies the concrete review work needed after engineering qualification.
The phase's required representative-user and independent reviews cannot be supplied
by synthetic test identities or Codex's examination of its own implementation.
The [delivery register](delivery-register.yaml) owns the resulting status and decision.

## Representative operator and accessibility — BL-P03-001

Product/quality supplies an application owner or representative operator, an observer,
and the exact browser/OS/managed-policy/assistive-technology combinations selected
through OP07. Use the synthetic Permit Desk intent, two tenant scopes, an author
grant, a separate reference administrator and a second authoring tab. Record the
tested source, Catalogue 1.0.1 contract, browser and assistive versions, policy,
task outcomes, relevant WCAG 2.2 AA criteria, defects and non-sensitive evidence IDs.

| Task | Observation required for completion |
| --- | --- |
| Create/import the complete application | Navigate by keyboard, identify selected tenant/environment, import the fixture, explain workload/WSD/domain and data/recovery intent, and verify the unsupported required control is still present. |
| Explain an invalid association | Submit an ordinary NIC in the wrong domain. Confirm the error is focused and announced, explain how to correct it, and verify the complete draft remains available. |
| Resolve an actual stale edit | Revise from two tabs, including JSON import in the losing tab. Explain the current-versus-draft differences, explicitly adopt the reviewed current base and publish without silently losing either tab's work. |
| Compare immutable revisions | Find the original and latest revision, identify changed compute, dependency and requirement values, distinguish unchanged history from current intent, and complete comparison at the declared zoom/reflow setting. |
| Recover an uncertain result | In the disposable qualification environment, lose an accepted response. Explain why the draft is locked and retry the unchanged command. Confirm one logical revision, its stable result and accessible status announcement. |
| Handle access changes and navigation | Revoke author membership, attempt another publication, restore history and navigate to the foreign tenant. Confirm protected fields remain unavailable and the remediation is understandable using the selected assistive technology. |
| Protect an unsaved draft | Cancel navigation away from an edited draft, then deliberately discard it. Confirm keyboard focus, confirmation behavior and tab-only draft retention match the user's expectation. |

No production credentials, native effects or operating deployment are needed for
these synthetic authoring tasks. Run the existing private fault harness for the
uncertain-response task; it does not add a product test endpoint. The automated
Chromium/Firefox/WebKit journeys establish their recorded engineering boundary,
not the operator's comprehension or managed-browser support.

## Criterion review — BL-P03-002

Catalogue, architecture/quality and product reviewers use the
[G03 procedure](../qualification/gate-reviews/g03.md) and engineering assessment.
An independent quality reviewer examines the original failure timelines, database
state and broker observations, rather than only the final page or test totals.

| Criterion | Evidence to examine | Accountable role |
| --- | --- | --- |
| G03.01 | Complete fixture, strict wire schema, immutable version chain, generated clients and browser intent/comparison results. | Catalogue owner |
| G03.02 | Domain/ownership/authority denial matrix, stale-writer result and rollback counts; current reference and owner checks. | Architecture and quality leads |
| G03.03 | Real PostgreSQL rollback and role denials, concurrent request ordering, original retry receipt, process restart, real broker fault/replay and post-revocation fact delivery. | Quality lead independent of feature author |
| G03.04 | Query/payload measurements and bounds, safe serialization, all declared operator tasks and accessibility observations above. | Product owner and representative operator |

Record actual reviewer identities, dates, immutable evidence references and an
assessment for every criterion. Resolve mandatory defects and rerun their affected
campaigns before entering the G03 decision in the register. Development authorization
and G00's accepted initial cardinalities do not need to be requested again.
