<a id="IK_01"></a>

Implementation converts a reviewed design into an observed, supportable service. Installation, qualification, production activation and continuing operation are distinct outcomes.

Baseline and related records: [DEL §3](../../governance/delivery-framework/3-apply-gate-dependencies-rather-than-numerical-order.md#DEL_03)  •  [EK §8](../../engineering/delivery-guide/8-build-test-and-implementation-handoff.md#EK_08)  •  [WD §9](../../solutions/internal-protected-workload/9-build-sequence-with-explicit-acceptance-dependencies.md#WD14_S09)


<a id="source-table-21"></a>

| Implementation output | Accountable role | Completion evidence |
| --- | --- | --- |
| IK-01 — Change scope, release freeze and execution authority | Change owner | Actual change reference, immutable artifacts, scope, participants and stop authority recorded. |
| IK-02 — Staging and installation readiness | Deployment lead | Supplier/asset checks, approved installation method, facility work, recovery access and staging results accepted. |
| IK-03 — P0–P1 bootstrap and foundation receipts | Foundation owner | Trusted independent access, minimum services and verified physical/network transport precede platform consumption. |
| IK-04 — P2 native platform build receipts | Selected platform owner | Installer and native resource changes match approved tuple; APIs, baseline and supported recovery observed. |
| IK-05 — P3 shared-service and boundary receipts | Service + edge owners | Denied boundary paths, service clients, return routing, names/trust/backup and management separation observed. |
| IK-06 — Restricted qualification fixture and test campaign | Assurance lead | Authorized disposable scope, actual observations and supporting control paths; no production qualification assumed. |
| IK-07 — G4 initial operational and recovery readiness | Service operations owner | Owners, support, monitoring, incident paths and required restore/recovery evidence accepted before activation. |
| IK-08 — P4–P5 tenant build and production activation | Service acceptance owner | G0/G1/G2, applicable initial G4, current tests and valid authority precede reversible activation. |
| IK-09 — As-built, defect and evidence records | Implementation + operations | Actual identities, configurations, departures, tests, evidence and owner acceptance are attributable. |
| IK-10 — P6 maintenance, migration and retirement | Lifecycle/data owners | Change requalification, fencing, retained-copy/key obligations, access withdrawal and safe disposal tracked. |

Use Implementation\_Tracker.xlsx for the execution record. A local workbook status is an index to evidence and authority; it is not an approval engine. Record actual operators and approvers rather than accepting the role names in this reference as assignments.
