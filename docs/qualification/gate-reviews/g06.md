# G06 review — Durable execution in simulation

This procedure applies the [canonical G06 criteria](../../implementation/gates.md) to the scope delivered by [P06](../../implementation/phases/p06.md). Use the [shared review process](README.md); the [delivery register](../../implementation/delivery-register.yaml) owns actual evidence references, reviewer identities and the gate decision.

**Review roles:** Product, qualification, security, lifecycle, assurance and SRE reviewers.

**Environment:** Integration with real PostgreSQL, broker and Temporal, controlled adapters and explicitly synthetic outcomes.

## Assemble the review packet

Q01/Q03/Q04 run manifests, operation/authority journals, fault timelines, evidence digests and alert/recovery observations.

Confirm the source/artifact identities, selected scope, authorization references, independent observation and evidence validity before judging results. Resolve missing artifacts as explicit review gaps.

## Review in this order

1. **G06.01:** Trace one application from catalogue intent through assessment, approval, durable admission, execution and assurance. Compare IDs across all contexts; verify the UI labels synthetic outcomes.
2. **G06.02:** Review stale/revoked authority, wrong epoch, ownership collision and unsupported operational tuple denials. Confirm isolated campaign credentials/endpoints cannot authorize production operations.
3. **G06.03:** Order every crash/lost-response timeline around acceptance. Compare journal to independent simulated readback; verify unknown results hold resource authority and prohibit blind retry/release.
4. **G06.04:** Inspect tamper/tenant denial, digest and redaction results, safe persisted-job restore, actual alert receipt and emergency stop. Check that absent native evidence remains distinguishable.

## Stop and corrective work

Any duplicate logical effect, unexplained authority gap, unheld unknown outcome or false native claim prevents closure.

Retain failed/missing cases and assign corrective work to the owning package with an unblock condition. A changed supported scope must be reflected in requirements coverage, the support matrix and the run manifest before another decision.

## Record the decision

Record an assessment for each G06 criterion, immutable evidence IDs and limitations, actual reviewer/date, blockers and the reviewed scope. Apply [status rules](../../implementation/status-model.md); a review document or a passing subset does not close the gate.

Identify material changes that require reruns, update the register, regenerate derived progress/traceability and state the next executable action. This gate review does not itself authorize unrelated native or production changes.
