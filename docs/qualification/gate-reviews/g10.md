# G10 review — Enterprise operating qualification

This procedure applies the [canonical G10 criteria](../../implementation/gates.md) to the scope delivered by [P10](../../implementation/phases/p10.md). Use the [shared review process](README.md); the [delivery register](../../implementation/delivery-register.yaml) owns actual evidence references, reviewer identities and the gate decision.

**Review roles:** SRE, performance, security, receiving service owner and independent qualification reviewers.

**Environment:** Representative preproduction and selected native labs using the release candidate and all tuples included for release.

## Assemble the review packet

Q09/Q10 performance, fault, restore, upgrade, installation and security evidence; receiving-team exercise and release dossier.

Confirm the source/artifact identities, selected scope, authorization references, independent observation and evidence validity before judging results. Resolve missing artifacts as explicit review gaps.

## Review in this order

1. **G10.01:** Compare measured workload mix, endpoint budgets, latency, failure-domain behavior and full recovery timings to the approved targets. Ensure load scope and excluded conditions are explicit.
2. **G10.02:** Follow read-only restoration of databases, histories, evidence, state and keys through epoch/native-state reconciliation to reviewed write enablement. Inspect mixed-version and incompatible-contract cases.
3. **G10.03:** Review required security findings, actual custody/sovereignty boundaries, rotation and key/identity loss. Check clean/restricted installation against the complete selected dependency closure.
4. **G10.04:** Reconcile candidate digests, native claims and rerun impact decisions. Observe alert receipt/on-call exercises and obtain the receiving owner’s actual support/limitation decision.

## Stop and corrective work

Unmet required operating targets, unsafe restore, unresolved mandatory security findings or unsupported release claims keep the gate open.

Retain failed/missing cases and assign corrective work to the owning package with an unblock condition. A changed supported scope must be reflected in requirements coverage, the support matrix and the run manifest before another decision.

## Record the decision

Record an assessment for each G10 criterion, immutable evidence IDs and limitations, actual reviewer/date, blockers and the reviewed scope. Apply [status rules](../../implementation/status-model.md); a review document or a passing subset does not close the gate.

Identify material changes that require reruns, update the register, regenerate derived progress/traceability and state the next executable action. This gate review does not itself authorize unrelated native or production changes.
