## Assemble the review

1. Pin source revision, dependency locks, seven principal service and selected worker build manifests, signatures/SBOMs and immutable image digests.
2. Obtain clean-runner build results, empty-environment installation observations, [Q01](../campaigns/q01-contract-and-tenancy.md) contract/tenant checks and applicable [Q09](../campaigns/q09-deployment-and-recovery.md) foundation exercises.
3. Confirm integration contains synthetic data and approved isolated dependencies; inspect actual endpoint restrictions and credentials instead of relying on environment names.

## Criterion examination

| Criterion | Review action |
| --- | --- |
| G01.01 | Reconcile locked inputs to built images; inspect clean builds/typechecks and evidence that a service change does not rebuild unrelated services. |
| G01.02 | Follow the empty-environment installation inventory; verify authenticated health, seeded fixtures and absence of production endpoints/credentials. |
| G01.03 | Inspect PHP/Python version/tenant/caller rejections, duplicate inbox handling and rollback of mutation plus outbox under real dependencies. |
| G01.04 | Match signatures/SBOM/manifest to digests; examine actual unsigned or mismatched artifact rejection before promotion. |
| G01.05 | Review runtime versus migration roles, denied cross-database/admin access and revoked/invalid workload identity outcomes. |
| G01.06 | Compare restored synthetic DB/evidence identity and digest; observe service restart, delivered alert and failed-deployment recovery with writes disabled. |

## Resolve the review

Every principal deployable and selected worker must be represented in the manifest and verification scope. A CI configuration file or a successful build on a dirty checkout is insufficient for reproducibility.

Investigate any failed negative admission, unauthorized dependency access, unverifiable artifact or incomplete restore before accepting the affected criterion. Record exact configuration/revision and a reproducible remedial action.

Store the review record with criterion assessments and evidence references, then update the [delivery register](../../implementation/delivery-register.yaml). Foundation recovery evidence covers only the exercised P01 scope; it does not close P10 coordinated recovery or establish operational acceptance.

## Reopen when

Rerun affected criteria after build/dependency/runtime changes, new deployables, contract-envelope changes, trust/admission configuration, database role changes or baseline recovery changes.
