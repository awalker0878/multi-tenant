The architecture separates administrative ownership, workload lifecycle, security-domain routing, and platform implementation. That separation is the key to both security and portability.

<!-- SOURCE-BLOCK HB10:72 END -->

<!-- SOURCE-BLOCK HB10:73 BEGIN -->


<a id="source-table-73"></a>

| Concept | Purpose | Examples of Implementation |
| --- | --- | --- |
| Tenant Namespace | Administrative ownership, quota, RBAC, accounting. | Prism project/RBAC; NSX project; Keystone project; external identity groups. |
| Workload Security Domain (WSD) | Lifecycle and security-policy unit for a workload or workload set. | Metadata, automation object, policy scope. |
| Security Domain Instance | An isolated routing/policy namespace associated with one zone class and authority scope. | Nutanix VPC; NSX Tier-1/project routing context; Neutron router/address domain. |
| Workload Network | Internetwork/segment in a Security Domain. | Overlay subnet; NSX segment; Neutron network/subnet. |
| Flow Intention | Desired communication outcome between identities/services. | Compiled to Flow/DFW/security-group/gateway rules. |
| ZIP / Security Edge | Controlled inter-zone path and boundary policy. | Firewall/security context, service insertion, routed security edge. |
| Service Binding | Explicit consumption of DNS, NTP, identity, logging, backup, etc. | Approved endpoint + route/policy generated by control plane. |
| Exposure | Approved connection to public, enterprise, partner, or other external domains. | Ingress service, controlled egress, external network attachment. |
