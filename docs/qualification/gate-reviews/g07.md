# G07 review — Native OpenStack provisioning

This procedure applies the [canonical G07 criteria](../../implementation/gates.md) to the scope delivered by [P07](../../implementation/phases/p07.md). Use the [shared review process](README.md); the [delivery register](../../implementation/delivery-register.yaml) owns actual evidence references, reviewer identities and the gate decision.

**Review roles:** Platform, service, security, SRE, application, governance and qualification reviewers.

**Environment:** Separately authorized native qualification lab matching the selected OpenStack tuple and tested network/service topology.

## Assemble the review packet

Q04/Q05/Q06 results, scoped site commissioning, native operation plan/backend identities, owner receipts, application restore and retirement records.

Confirm the source/artifact identities, selected scope, authorization references, independent observation and evidence validity before judging results. Resolve missing artifacts as explicit review gaps.

## Review in this order

1. **G07.01:** Reconcile commissioning scope and every native-plan/artifact identity with native observations. Review real guest/service owner receipts and readiness before activation.
2. **G07.02:** Inspect positive and negative traffic across same-host, same-subnet, inter-host and relevant edge/IPv6/return paths. Review wrong-plan/scope/ownership denials before native mutation.
3. **G07.03:** Inspect partial provision, restart, lost response, revocation and failed activation. Compare authoritative native state, journal and reservation receipts before retries; verify actual application restore.
4. **G07.04:** Review separate retirement authority, retention/data/key handling, deletion observations and allocation releases. Compare the supported tuple/operation limits to the complete native evidence set.

## Stop and corrective work

Unverified service readiness, mandatory isolation failure, unreconciled native uncertainty or deletion outside owned scope blocks closure.

Retain failed/missing cases and assign corrective work to the owning package with an unblock condition. A changed supported scope must be reflected in requirements coverage, the support matrix and the run manifest before another decision.

## Record the decision

Record an assessment for each G07 criterion, immutable evidence IDs and limitations, actual reviewer/date, blockers and the reviewed scope. Apply [status rules](../../implementation/status-model.md); a review document or a passing subset does not close the gate.

Identify material changes that require reruns, update the register, regenerate derived progress/traceability and state the next executable action. This gate review does not itself authorize unrelated native or production changes.
