# G03 — Application catalogue and workspace review

Review P03 against G03.01–G03.04 in the [gate specification](../../implementation/gates.md), using [P03 work packages](../../implementation/phases/p03.md). Catalogue and architecture owners review domain behavior; quality/product reviewers assess persistence and operator tasks.

## Assemble the review

1. Pin the domain/contract version, synthetic Permit Desk manifest, permitted tenant/domain relationships and application acceptance scope.
2. Obtain [Q01](../campaigns/q01-contract-and-tenancy.md) invariant, concurrency, retry, outbox/replay and browser reports from the actual catalogue/API/UI revision.
3. Confirm tests use real integration persistence and broker where required, with independent authoritative state observations and preserved failure timelines.

## Criterion examination

| Criterion | Review action |
| --- | --- |
| G03.01 | Register/revise the multi-workload, multi-domain application; inspect immutable history and confirm logical intent is separate from native observation. |
| G03.02 | Examine cross-tenant/domain, dangling-reference, dependency-cycle and concurrent stale-edit rejection with no partial domain changes. |
| G03.03 | Compare duplicate command, outbox failure, restart and event replay to authoritative revision/event counts; confirm exactly one logical intent per accepted command. |
| G03.04 | Observe owners understanding validation errors, comparing revisions and completing the declared task with required keyboard/accessibility behavior. |

## Resolve the review

Inspect the entire revision chain and event record, not only the final UI view. A projection that eventually looks correct cannot conceal a rolled-back mutation event, transient disclosure or duplicate intent.

Separate an invalid domain model from a valid model rejected by policy; the operator must receive an actionable explanation consistent with the authoritative service. Preserve unresolved usability or accessibility defects with the affected task.

Record the review's actual source/contract/fixture revisions, criterion assessments, evidence IDs, reviewer/date and blockers. Store the decision solely in the [delivery register](../../implementation/delivery-register.yaml); catalogue completion does not establish native deployment support.

## Reopen when

Rerun affected checks after aggregate/cardinality changes, reference/cycle validation changes, concurrency/idempotency semantics, transaction/outbox behavior or revision/editor UX changes.
