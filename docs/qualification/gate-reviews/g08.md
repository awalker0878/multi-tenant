# G08 review — VMware-to-OpenStack migration

This procedure applies the [canonical G08 criteria](../../implementation/gates.md) to the scope delivered by [P08](../../implementation/phases/p08.md). Use the [shared review process](README.md); the [delivery register](../../implementation/delivery-register.yaml) owns actual evidence references, reviewer identities and the gate decision.

**Review roles:** Application, platform, security, SRE, service, independent observer and assurance reviewers.

**Environment:** Authorized native migration lab with exact selected VMware→OpenStack offline method, guest/data profile and service/policy topology.

## Assemble the review packet

Q07 source/target manifests and fault records, Q05/Q06 service/policy evidence, transfer integrity, writer/traffic timeline and post-write recovery data.

Confirm the source/artifact identities, selected scope, authorization references, independent observation and evidence validity before judging results. Resolve missing artifacts as explicit review gaps.

## Review in this order

1. **G08.01:** Reconcile every dataset, identity and consistency group to the accepted method. Inspect business-effect suppression in rehearsal and actual correctness/outage measurements.
2. **G08.02:** Order independent source/other-writer fencing, final synchronization, integrity acceptance and target traffic/write events. Review denied stale authority and unfenced-source attempts.
3. **G08.03:** Assess pre-target-write rollback separately from recovery after a committed target change. Verify that source-return reconciliation or forward recovery preserves the known change within accepted objectives.
4. **G08.04:** Review actual policy/service availability and data/outage objectives, source retention and separately authorized retirement criteria. Restrict support to the observed direction, method and exact tuple.

## Stop and corrective work

Missing dataset coverage, ambiguous writer authority, discarded accepted target changes or unproved post-write recovery prevents route acceptance.

Retain failed/missing cases and assign corrective work to the owning package with an unblock condition. A changed supported scope must be reflected in requirements coverage, the support matrix and the run manifest before another decision.

## Record the decision

Record an assessment for each G08 criterion, immutable evidence IDs and limitations, actual reviewer/date, blockers and the reviewed scope. Apply [status rules](../../implementation/status-model.md); a review document or a passing subset does not close the gate.

Identify material changes that require reruns, update the register, regenerate derived progress/traceability and state the next executable action. This gate review does not itself authorize unrelated native or production changes.
