# API configuration and Console review qualification

This increment implements the existing API-first OpenStack configuration baseline.
Inventory pulls configured options and advertised features; administrators validate
the observations, explain include/exclude overrides and enter values unavailable
through standard APIs. Saved reviews and confirmations retain scoped, immutable
provenance. No new architecture decision is introduced.

The [qualification index](qualification-index.json) binds original hosted archives,
source files, command logs and artifact hashes to their measured revisions. These
are E1/E2 software and synthetic-provider checks. No actual OpenStack installation,
native operation or release is E3-qualified. P07 and G07 remain incomplete.

| Boundary | Verification |
| --- | --- |
| Inventory persistence | Real PostgreSQL runtime role; immutable API facts, review revisions and confirmations; idempotency, revision conflicts, tenant/site isolation, freshness and revocation |
| OpenStack collector | Pinned TLS GETs, fixed routes and explicit microversions; 18 query projections including six optional service streams; secret-field removal, foreign scope rejection and incomplete-list holds |
| Administrator review | Immutable observed findings, required capability selection, reasoned overrides, allowlisted manual references, fresh-generation confirmation and rejection of forged API/authority fields |
| Compiled Console | API pull, save, empty-object handling, manual value persistence after reload, capability identity/order, confirmation, mobile layout and current access revocation in Chromium, Firefox and WebKit |
| Contract compatibility | Original v1 bytes preserved; additive inventory/collection/event v1.1 contracts and generated clients; frozen-contract gate retained |

The [version register](../../../docs/implementation/openstack-version-qualification.md)
starts with 2026.2 Hibiscus. Its documentation assessment does not substitute for
an installed API range, working backend or native operation qualification. Current
collection bounds, optional-stream requirements and unimplemented provider-specific
configuration remain explicit there.
