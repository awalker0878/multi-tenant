## Completed implementation and limits

The [support increment](../../implementation/p02-support-access.md) enforces exact
membership/grant diagnostics, separate tenant/security decisions, fresh activation
of one executor session, at most one-hour validity, current provider signing material
and authority on every use, immutable audit and independent post-use review. Runtime
cannot rewrite/delete its immutable bindings, approvals, reviews, audit or event
payloads. Real PostgreSQL races prove serialization and revocation-before-admission;
full-schema restore preserves terminal history. Protected data is returned only after
the admission/outbox commits. Broker events carry minimal audit references, never
permits or incident/session payloads. This is an API workflow, with no new Console
support screen or native effect. Concurrency isolates locking with synthetic trust
observations; operated issuer/custody topology remains unqualified.


The [installation consumer](../../implementation/p02-console-notifications.md)
accepts all twelve published identity routes alongside five tenant routes through
one event-ID namespace. Only settings changes and activation update the setup
hint. Current Governance settings authorization precedes its disclosure. The
shared bounded polling component preserves unsaved forms and clears write-only
secret drafts only when the user explicitly refreshes. Events never confer access.

The [recovery custody increment](../../implementation/p02-recovery-custody.md)
adds an external custody CLI and owner-only, two-person signed reconciliation to
the admission fence. It revokes stale sessions/delegations/grants/approvals, retains
only explicitly reconciled memberships and suspends other tenants. Every current
workload credential must be distinct and different from every declared prior one.
A separate signed post-state authorization, immutable database confirmation and
custodian release precede fresh OIDC sign-in. Runtime cannot rebind or rewrite the
receipts/releases. The original bootstrap remains retired; no automatic reset,
startup adoption or recovery HTTP endpoint is added. Operators must still hold and
rotate custody before restore and drain previously admitted work. The executable
[operator procedure](../../operations/runbooks/identity-recovery-custody.md) includes
lost-key/crash containment and explicitly unsupported pre-activation reset. Actual
host, key, backup, mount and human independence remain OP03/OP05/OP06 evidence.

Catalogue's real resources and Console-to-Catalogue integration belong to P03;
the real plan producer belongs to P05.04; immediate native-effect rechecks belong
to P06.03. No synthetic approval observation is a native permit. Broker HA/store
recovery, full operating acceptance and RTO/RPO retain their defined later gates.
