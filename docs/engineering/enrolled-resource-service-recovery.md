# Enrolled resource, service and recovery owners

The selected application path now composes the existing capacity database,
authoritative NetBox owner and B09/B10/B11 PostgreSQL owners with concrete native
credential and readback clients. This is executable implementation and local
protocol evidence. It does not commission an installed site, qualify a route,
authorize production activation or establish actual native writer exclusion.

## Immutable ownership

The protected execution selection binds the complete resource bundle, delivery
graph, nonsecret packet bytes and exact native scopes. The resource-bundle digest
excludes the admitted job and plan digest to avoid a cyclic digest. The actual
request and original intent bind the current admission separately.

`reservation_identity_digest` hashes the originally charged owner, reservation,
request, pool, units and envelope/resource bindings. Confirmation timestamps,
status and observation metadata do not silently change this identity. Existing
snapshots using another digest require retained-state review. They are not
automatically reinterpreted as newly admitted resources.

Planned creation and service stages use the existing `planned_resource_ownership`,
`native_operation_leases` and `native_operation_intents` tables. A planned
deployment has no invented native UUID. Service bindings project one exact
selected IPAM, DNS or quota stage from that same resource owner. A service grant
cannot be used as a VM creation grant. The native UUIDs enter ownership only after
independent current readback of the actual selected children.

## Process-local enrollment API

| Concrete owner | Required enrolled inputs | Effect and readback |
| --- | --- | --- |
| `NativeReadEnrollment` | Actual `WorkerCommandRuntime`, current `AdmittedInput`, protected selection digest, same `CredentialBroker` and `VaultCredentialConsumer` | Independent `DISCOVER_READ` contact, exact scope and current mTLS/B10 checks before and after each exchange |
| `OpenStackNativeReadbackOwner` | Read enrollment, commissioned Keystone v3 URL and CA, private custody directory, exact protected bundle loader | Actual project-reader authentication, Nova/Cinder/Neutron child IDs, flavor/storage/attachment/policy checks and measured destination occupancy |
| `EnrolledServiceReadbackOwner` | Different enrolled read worker and private custody directory | Actual NetBox allocation, authoritative DNS generation or exact project quota readback |
| `EnrolledServiceProvisioningRuntime` | Original command runtime, `PlannedServiceLease`, `PlannedServiceRegistry`, broker/consumer, existing `NetBoxResourceTransactions`, bundle loader and separate readback owner | Fixed selected IPAM reserve/confirm, primary DNS registration/generation switch and quota apply; one claimed original intent |
| `EnrolledDnsPropagationRuntime` | Actual read command runtime, broker/consumer, service readback owner, same service registry and private custody directory | QUERY-only signed primary, secondary and recursive observations; two sweeps with exact positive controls |
| `VaultNativeCredentialLeaseStore` | Existing B10 PostgreSQL connection and private custody directory | Append-only attempt, wrapping digest and backend lease provenance, recorded before issuance and consumption |
| `VaultRecoveryRevoker` | New actual recovery admission, same custody/issuer, original bundle and newly enrolled cleanup worker | Exact synchronous Vault lease revocation and authenticated recontact; no prefix/force revocation or native deletion |

The service methods have the fixed delivery signature
`run_step(admitted, selection, delivery, step, packet, directory, base, source_root)`.
The primary owner also exposes `inspect_resolved` with that signature. It reads a
resolved original intent and obtains a fresh independent observation, returning
the original operation ID, request digest and receipt. Propagation
`inspect_resolved` returns a fresh `hosting-enrolled-dns-propagation/1` record
bound to the same primary operation, request and full receipt digest.

Native reads inside a proof transaction reuse its actual non-autocommit
PostgreSQL cursor. `CredentialBroker.acquire_observation` supports only
`DISCOVER_READ` and uses the complete existing B10 verification path. This avoids
opening a second connection which waits on the same reader job locks. It does not
provide an alternate mutation credential port.

## Service authority and completion

Vault roles issue exact versioned data projections. NetBox uses a v2 bearer token
whose actual token/user ID, expiry and write setting are recontacted, with exact
namespace/owner allocation checks. DNS uses a dynamic TSIG binding for the exact
server, zone, owner and selected RR names/types. Quota uses the selected native
project and reviewed entitlement request. Extra credentials and changed endpoints
are rejected. Authentication refresh does not change the selected records, view
set, source, input bytes or reviewed graph.

`dns_cutover` requires a previously independently resolved `DNS_CHANGE`, its
actual original receipt, current owned marker and exact before/after generation.
The existing DNS ledger records a single attempt before the RFC2136 UPDATE.
Unknown responses preserve the original intent. The separate propagation owner
issues no UPDATE, including recovery of an interrupted observation.

`NativeOperationRegistry.acknowledge_current` supports a known completed original
attempt while its current grant and owner are still live. It requires fresh
independent `EFFECT_PRESENT`, actual native quiescence, the exact accepted task ID
when one exists and current proof recontact. It cannot resolve an already
uncertain, revoked or expired attempt. Synchronous completion does not invent a
native task ID. Recovery still requires separately approved old-writer exclusion.

Windows delivery uses the fixed `windows_guest_apply` stage and the separately
enrolled certificate-only WinRM owner. Its completion binds the selected native
guest, descriptor, source and listener CA, and retains
`CONFIGURED_REQUIRES_NATIVE_ACCEPTANCE`. All service/Windows results retain
`native_acceptance=false` and `production_activation=false`.

## Newly admitted recovery

The narrow canonical `spec.resourceRecovery` binds the original job, original
plan/selection/bundle/reservation digests, sorted original operation IDs, incident
and selected cleanup/release actions. A distinct new running B09 job requires
current approvals, its own signed operating acceptance, qualification and
installed operating-instance admission. The original job and every earlier
related cleanup job must be stopped or revoked against their own plan authority.
All original intents and the original capacity charge remain unchanged.

The credential-fencing admission port exempts only the exact selected original
and earlier related cleanup uncertainty while the fixed Vault revoker disables
the old credentials. Unrelated uncertainty and containment still hold it. This
port grants no native cleanup, release, retry or old-grant resurrection. Native
cleanup/refund requires resolved original intents, independent native quiescence,
actual old-writer exclusion and observed cleanup before the capacity refund.

Lost issuance or unwrap responses leave an unconsumed custody attempt. Neither
lease expiry nor an operator success assertion closes it. Vault fencing alone
does not exclude an already queued native task, an established remote command or
a local policy writer. Those require their concrete native exclusion owners.

## Validation and remaining evidence

Focused local checks exercise actual pinned TLS Vault issuance/unwrap and
Keystone/Nova/Cinder/Neutron readback, signed TCP DNS sweeps, revoked per-exchange
authority, immutable service selection and exact new recovery admission. Native
server responses and B10 authority in loopback tests are explicitly synthetic.
Opt-in PostgreSQL tests cover current native acknowledgment, append-only custody,
RLS, lost issuance and exact persisted grant bindings. PostgreSQL tests require
the isolated runtime/migration/enrollment roles; they are skipped without them.

Before qualification, run those tests against real PostgreSQL and the installed
wheel, then commission actual mTLS workers, dynamic Vault plugins/roles, NetBox
permissions, TSIG primary/views and the exact OpenStack API/policy tuple. The
reader policy must expose the actual Cinder tenant ownership needed by the
contract. Missing or denied object reads are not absence evidence.

The fixed resource recovery workflow uses a newly admitted recovery plan rather
than restarting the revoked application graph. Its installed
`ResourceRecoveryActivityRouter` owns seven fixed activities and selects only
immutable process-enrolled `ResourceRecoveryRuntimeBindings` by actual job ID.
An absent binding holds without contacting a native writer. Cleanup requires
independently fenced resolution of every old intent before one actual DELETE
per originally observed child. The compiled OpenStack adapter authenticates a
restricted project cleanup role. It treats the actual HTTP request reference as
a request reference; it never invents a native task. Missing Nova servers require
the successful, finished hard-delete action event in addition to two independent
absence sweeps. Volumes require detached storage and complete no-snapshot/backup
observations. Denials, generic 404 responses and unfinished events retain charge.
Release-only recovery performs no credential revoke or native DELETE.

`CompletedNativeGrantRetirement` rechecks the current original grant, mTLS peer
and independently resolved native observation, seals issuance in the existing
SQL0033 append-only custody table, then synchronously revokes and looks up every
exact consumed backend lease. Lost or unconsumed issuance remains held after
sealing. No lease expiry becomes an exclusion proof. Planned creation, selected
services and selected cleanup require this transition before their completion.

`ApplicationResourceAccounting` independently confirms both destination
OpenStack occupancy and the retained VMware source through their concrete reader
owners. Confirmation occurs after native acknowledgment and credential retirement,
before TARGET association. Nonzero temporary/snapshot target purposes need their
separate counted owner. The retained-source owner refuses native snapshot chains;
detached backings require their actual native datastore read owner and stay charged.

`StagedApplicationResourceAuthority` preserves the original SQLite charge and
native IDs for a separately approved CUTOVER/DB job. Each use checks the current
canonical staged handover, original confirmed receipt, current source/target
occupancy and every old sealed credential lease through an independent enrolled
reader. SQL0035 records an immutable association with the original charge; it
does not allocate, rekey or refund capacity. `StagedPlannedLeaseAuthority` keeps
the same B10 lease owner, accepts an immutable actual job-to-owner map once
before worker registration and seals that enrollment. Only exact selected DNS
generation changes may use its staged service projection. Further target power
and management-port phases require their separately resolved native intents and
fresh current-state readback; the original quarantine snapshot alone cannot
authorize guest reachability.

Local tests run four real Temporal recovery histories with replay, pinned TLS
Vault/native HTTP contacts, hard-delete event checks, lost acknowledgment/no-repeat
negatives and sealed enrollment rejection. The opt-in SQL test exercises actual
foreign-job rejection and refuses current acknowledgment of an uncertain intent.
These tests do not qualify a real OpenStack, vCenter, Vault backend, NetBox or DNS
installation. VMware/AHV target creation, native retained-source refund and
automatic queued-task cancellation remain separate work. Each additional platform
direction and method requires its own owner and native evidence.
